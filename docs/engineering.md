# 共享工程规范

本文件是 Codex 和 Claude Code 的共享规则。职责分别见根目录的 Agent 指令；总体目标见 [整体规划](project-roadmap.md)，架构见 [架构说明](architecture.md)。

## 工作区与变更范围

- 使用中文；以当前 worktree 的 Git 根目录为工作范围。开始时检查分支、HEAD 和未提交改动，保留既有用户资料。
- 每个任务一个实现分支、一个 Owner 和一个独立 Reviewer。单个物理工作目录同时只有一个写入者。
- 修改范围、接口和验收条件写入任务卡。授权范围内的实现无需反复确认，超出范围的重大设计变更记录 ADR 并提交用户决策。
- 不擅自丢弃或覆盖他人改动，不为通过检查而删除必要测试，不进行无关重构。
- 工程规范、架构、任务卡分别保存规则、设计事实和任务状态；避免复制同一事实产生多个版本。

## 架构与代码

- Python 3.11 为当前开发基线；采用类型提示和已有 Ruff/mypy 约定。框架依赖以实际功能需要引入，并说明理由、同步锁文件。
- HTTP 是接入层。Runtime、Context、工具和评测核心应可由离线入口调用，不反向依赖 FastAPI。
- Agent 可见输入与评测答案分离；Runtime/Context 不读取黄金答案，Evaluator 独立评分。
- 明确错误类型、终止原因、资源释放与取消行为，不静默吞异常。
- 工具定义参数 Schema、超时、有限重试及副作用。重试、幂等键和恢复必须匹配工具实际支持的语义，不声称任意外部操作恰好执行一次。
- 关键状态转换、工具执行和模型调用保留 trace/run 标识及可核验结果。实验数据必须记录配置与版本。

## 配置与环境

- 每个 worktree 独立维护 `.venv`、`.env` 和产物，环境变量可以覆盖本地配置。
- 当前 `Settings` 的 `.env` 相对于进程工作目录加载，因此服务从当前 worktree 根目录启动；不得自动读取另一个工作区的密钥文件。
- 后续 CLI/Worker 引入时明确配置传递方式；目前不宣称支持从任意目录自动找到服务配置。
- 数据库、Compose 项目、端口等外部资源在接入时按工作区隔离；Git worktree 不提供外部资源隔离。
- 不提交密钥、实际 `.env`、个人模型配置或未经允许公开的数据。

## 统一验证

从项目内任意目录调用对应路径的 `scripts/verify.sh`，脚本会回到其所在工作区根目录：

```bash
./scripts/verify.sh
```

顺序为：锁定依赖安装 → Ruff 检查及格式检查 → mypy → pytest → 构建 → 锁定运行依赖安装 → 仓库外 wheel 安装与应用创建检查。CI 调用同一入口。脚本遇到失败停止，保留非零退出码，不自动格式化或调用真实模型。

本地先安装 uv 0.12.23（与 CI 一致）及 Python 3.11。网络、工具缺失或外部资源不可用时，明确记录阻塞；不得改成无锁安装或跳过失败后声称通过。

按变更增加有意义的验证，报告完整命令、结果、环境、时间和失败原因。当前 HTTP 测试只覆盖应用创建与请求，不代表真实进程启动、lifespan 或外部服务就绪验证。

## 交付与完成标准

- 交付包括任务目标、实现版本、变更、自查、实际验证、未解决问题和下一步，使用 [交接模板](collaboration/handoff.md)。
- 实现提交先产生 SHA，交接记录在后续文档变更中引用该 SHA，避免要求提交包含自身哈希。
- Reviewer 绑定 base/head，使用 [审查模板](collaboration/review.md)。业务代码、配置、依赖或验收行为变化时，更新审查目标；纯任务索引或交接报告变更单独说明。
- DONE 要求满足验收条件、无未解决阻断发现、验证证据齐全，并经用户验收合并。自查和 CI 不代替独立 Review。
- 提交、推送和合并遵循当前用户授权。任务 Prompt 或记录中的“下一步”不自动授权联系另一个 Agent、启动工作流或发布内容。
- 未经当前消息明确要求，不主动使用 deep-research、工作流或子 Agent；需要联网时直接使用搜索和页面读取。
